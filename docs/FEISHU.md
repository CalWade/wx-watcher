# 飞书接入与测试

建议使用单独的内部测试群完成首次接入。机器人发送建议，同事人工确认后回复客户。

## 路径 A：复用已有 Lark CLI

1. 确认本机 `lark-cli` 已配置自己的飞书应用，并可以用 bot 身份操作。
2. 在目标群的「群机器人」中添加该应用机器人。
3. 在 NoteBridge 选择「复用已有 Lark CLI」，保存连接方式。
4. 点击「获取机器人所在群」，选择准确的接收群。
5. 点击「发送测试并回读」，在飞书确认测试内容和发送身份。

工具显式使用 bot，不自动退回用户身份，不需要给模型提供飞书凭据。
群邀请链接不是 chat_id，不能直接当收件人使用。群列表来自当前机器人的实际可访问范围。

## 路径 B：自建飞书应用

1. 在 [飞书开放平台](https://open.feishu.cn/)创建企业自建应用，启用机器人能力。
2. 可先从 NoteBridge 自建应用区域下载权限 JSON，在飞书「权限管理 → 批量导入」导入，
   然后核对权限名称与当前平台要求。所需范围为：机器人发消息、列出所在群、读取测试消息。
   平台权限名称和可用范围以当时控制台为准；通常涉及
   `im:message:send_as_bot`、`im:chat:readonly`、`im:message:readonly`。
3. 按组织要求发布/启用应用并完成审批。开发版本、可用范围和权限审批是不同步骤。
4. 将机器人添加到测试群。未入群的机器人不能向该群发送消息。
5. 在 NoteBridge 选择「自建飞书应用」，填写 App ID 与 App Secret，点击保存。
6. App Secret 存入 Keychain，配置只记录引用；界面保存后清空输入框。
7. 获取群列表、选择接收群、发送测试并回读。

应用权限按 tenant_access_token 工作，不应使用用户 OAuth 来绕过机器人权限问题。
官方接口：[发消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)、
[群列表](https://open.feishu.cn/document/server-docs/im-v1/chat/list)、
[读取消息](https://open.feishu.cn/document/server-docs/im-v1/message/get)。

## 开始投递建议

完成业务资料和 DSH 测试后，在「接入设置」第 5 步开启自动投递并保存。
开启时需检查已有草稿：已验证的待发建议也可能被投递。
系统固定使用配置的机器人和接收群；模型不能更改收件人。

建议包含原问题、拟回复内容、待内部确认事项和判断依据。
使用纯文本，屏蔽会创建群提及的标记，不按模型文字下载远程图片。

## 失败处理

- 群为空：确认添加的是当前配置的应用机器人，检查应用可用范围和群成员关系。
- 权限不足：在开放平台检查应用权限和发布审批；不反复登录个人账号解决 bot 权限。
- 发送超时：不代表一定未送达。先到群里核对，任务进入待检查状态。
- 幂等键的有效窗口有限；不能在任意长时间后盲目重发并声称绝不重复。
- 读取失败：可能发送已成功但读权限缺失，先检查目标群和所需读取权限。

更换连接方式或飞书应用后，需要重新选择接收群，自动投递会关闭，避免沿用旧应用的接收目标。
