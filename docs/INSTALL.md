# 安装与首次运行

从 0.2 升级：先阅读 [NoteBridge 更名与数据迁移](MIGRATION.md)，已有密钥继续复用。

第一次使用请从 [新机器完整指南（含界面示例）](FIRST_RUN.md) 开始。主应用已包含取钥，无需同时安装 Setup。

## 1. 确认适用范围

目前面向 Apple Silicon Mac。原生界面的源码目标是 macOS 14；实际应用最低版本取所有打包依赖的最大值。
本机发布的 0.4.5 安装包因 SQLCipher/OpenSSL 依赖要求 **macOS 27.0+**，
安装包 Info.plist 与 build-manifest.json 会如实记录。真实整合组合在 README 中列出。
首次取钥只放行已验证的微信构建；数据库读取、应用能启动和取钥成功是不同的验收项。
请只连接本人账号或有明确处理权限的数据。

## 2. 使用 Mac 应用

从仓库 Releases 下载与你芯片对应的构建，核对发布页 SHA-256。
将 `NoteBridge.app` 拖入「应用程序」后打开；独立凭据用途可从发布页另外下载 Setup ZIP。DMG 只放主应用。
两个入口使用同一个本机凭据与账号配置，不需要复制密钥。

请检查发布页的签名状态。Developer ID 签名与公证需要维护者配置凭据；临时签名构建
用于开发和验证。若系统拒绝未公证应用，按 macOS 对单个应用的正常确认流程处理，
或从源码构建。不要关闭 Gatekeeper、SIP 或全局安全设置。

正常结果：左侧只有「工作台」和「接入设置」，其他功能在左下角「更多」中。首次接入从第 1 步连接微信开始。
关闭窗口后应用仍在菜单栏；选择「退出应用与后台服务」才退出本应用启动的后台任务。

## 3. 从源码运行

先复用已有环境；缺少时安装 [uv](https://docs.astral.sh/uv/) 和 SQLCipher。
Homebrew 用户可执行：

```sh
brew install uv sqlcipher
git clone https://github.com/CalWade/wx-watcher.git
cd wx-watcher
uv sync --frozen
swift build --package-path native -c release
codesign --force --sign - native/.build/release/notebridge-access
uv run notebridge desktop
```

上面的临时签名使本地构建的凭据工具具有代码身份；未签名工具可能被 Keychain 拒绝。
正式分发仍应使用稳定 Developer ID。原生模块需要 Swift 6 和适用的 Apple 开发者工具。`xcode-select --install` 可安装 CLT，
但取钥调试器仍需单独通过兼容检查：曾验证的 macOS 27 环境使用 Xcode 内的 LLDB 2103，
旧 LLDB 1600 在附加时崩溃。工具会在修改微信之前拒绝不合适的组合。
不要为通过检查盲目更改系统 Xcode 选择或关闭系统保护。

`desktop` 自动打开浏览器；Mac 应用与浏览器使用同一控制台。浏览器开发入口的路径
选择通过输入绝对路径完成，Mac 应用提供系统文件选择器。

## 4. 完成向导

1. 新机首页点击「首次连接微信」，检查环境；无需提前登录微信或发送消息。
2. 向导自动识别资料；多个历史账号直接显示选择框，也可选择「登录其他账号」。无资料时监听就绪后登录，程序自动等待资料生成并验证。
3. 已有密钥：在高级选项选择文件，点击「验证并存入 Keychain」。文件应仅本人可读写，权限 600。
4. 无密钥：[按照新机指南](FIRST_RUN.md)完成一次性捕获与恢复，再点「下一步：选择会话」。
5. 回到「接入设置」第 2 步搜索群名，选择准确会话。初次建议用文件传输助手。
6. [接入 DSH](DSH.md)，测试模型与费用记录。
7. [接入飞书](FEISHU.md)，选择测试群，试发并回读。
8. 按需在「更多 → 业务资料与规则」补充资料，在第 5 步确认运行选项。
9. 点击「测试并开始运行」：系统验证凭据、执行一次模型调用、检查工具数与费用、向所选
   飞书群发送一条测试并核对回读，全部通过后启动。这个按钮会产生实际模型用量和飞书测试消息。

系统隐私权限、管理员授权和 Keychain 权限不同。缺少权限时按界面明确提示处理；
**新安装应用不继承终端、Codex 或旧版签名的完整磁盘访问权限。**
原生应用会对所选微信目录进行访问检测，并尝试触发系统登记；本机 macOS 27 未验证自动列出成功。在取钥向导展开「权限帮助」，点击「完整磁盘访问设置」，
找到 NoteBridge 后开启开关。如果系统未自动列出，可将权限帮助窗口中的应用图标直接拖入权限列表；不需要寻找安装路径。
也可用系统 `+` 选择 `/Applications/NoteBridge.app`。
开启后点击权限帮助窗口中的「重新连接」，系统会停止自有后台并重新打开应用。
只使用独立 Setup 时对实际运行的 Setup 授权。
这一步是系统隐私授权；不需要重新获取数据库密钥。
已有权限和有效密钥会直接复用。工具不会读取或保存系统密码。

## 5. 验证完成

监听开启后，在选定微信会话发送一个明确问题，例如“请问培训几点开始？”。
在「回复建议」查看新任务，随后在飞书确认建议、判断依据和待确认事项。
微信发送时间、数据库观察、模型耗时、飞书送达是不同时间点，不能混为一个指标。
首次基线中的旧消息不会自动广播。

## 6. 常见安装问题

| 现象 | 处理 |
| --- | --- |
| 找不到 SQLCipher | 确认命令在 PATH，或旧版配置显式指定 `sqlcipher`；应用包需检查引擎是否完整 |
| 找不到 notebridge-access | 源码用户先构建 native 包；应用用户重新校验构建完整性 |
| 微信目录读取被拒绝 | 在系统隐私设置中授权实际运行的应用；管理员权限不能替代隐私授权 |
| Keychain 拒绝访问 | 使用稳定签名的工具，在系统提示中确认；不要重新取钥来解决钥匙串问题 |
| DSH 未就绪 | 打开 DSH，安装 cost-meter 与桥接，查看 DSH 插件日志 |
| 端口占用 | 暂停冲突实例，或使用独立配置和不同端口；不要直接杀掉不明进程 |

下一步：[日常运维、备份和卸载](OPERATIONS.md)。


## 哪些事情由系统代办

- 原生应用检测微信目录访问并尝试引导系统登记；未自动列出时提供图标拖入入口，权限决定由本人在 macOS 完成。
- 只有一个活跃微信账号时预选其数据库目录；已保存凭据直接复用。
- DSH 保持原模型渠道与账本，桥接相同版本不反复重装。费用插件已安装时复用，缺少时调用
  已安装 Desktop 的官方插件安装入口；不为此另装全局 Node/Python 环境。
- 没有 Lark CLI 时默认展示自建应用接入，提供权限导入配置；已有 CLI 连接直接复用。
- 同页选择两个会话后一次完成联调和启动；端口被其他程序占用时选取可用端口并保存。
- 监控进程异常退出有限重启，配置和任务保留；退出所属应用会停止后台。

仍需本人决定：要处理的微信账号/会话、飞书接收群、业务资料与模型渠道；仍需本人操作：
必要系统授权、首次微信登录/手机确认，以及组织要求的飞书应用发布审批。工具不会代填或保存系统密码。
自动权限登记是否出现由 macOS 版本决定；它不等同于已经获得授权。
