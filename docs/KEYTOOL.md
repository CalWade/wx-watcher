# 微信凭据工具：获取、验证、保存与恢复

## 原理和边界

日常服务使用已保存的主密钥派生各数据库的密钥，并只读查询副本。
首次获取主密钥采用 GreenBubbles / wcdb-key-tool 的公开方法：在登录时的
`CCKeyDerivationPBKDF` 调用处用 LLDB 读取参数，然后用 SQLCipher 页认证验证。
它不是密码暴力破解，也不是长期注入式消息监听；首次过程仍涉及客户端重签和调试附加。
不能承诺零风控。来源、固定版本和补丁见 [THIRD_PARTY.md](../THIRD_PARTY.md)。

新机器请先看 [从零使用与界面示例](FIRST_RUN.md)。主应用内已有完整向导，独立 Setup 为可选入口。

## 已有密钥时直接复用

打开「微信凭据」的「已有密钥 / 加密备份 / 手动选择账号（高级选项）」，选择正确账号的 `db_storage`，选择已有密钥文件，点击导入。
文件格式支持 64 个十六进制字符，或含 `passphrase`、`master_key`、`raw_key` 的 JSON。
密钥不得放在命令参数、截图、聊天、Issue 或模型提示词中。

成功标志：全部发现的数据库盐校验通过，界面显示 Keychain 已保存；导入过程会验证
存入后能读回相同字节。配置仅保存一个随机凭据引用。原文件不会自动删除。
在读取应用验证成功并完成备份之后，再按需要清理多余副本。

## 第一次取钥

### A. 环境检查

1. 全新 Mac 需先正常登录官方微信并生成本地消息资料；已有资料的账号可以从登录页开始。
2. 首页点击「首次连接微信（没有密钥）」，在向导点击「检查并识别微信账号」。单个活跃账号自动选择，不需要手填目录。
3. 只读检查微信构建、Apple Silicon、调试器、资料读取与目标账号；App 管理权限在实际开始前另行检查。权限由实际原生工具验证，不能用开发终端的权限替代。
4. 不支持的构建停止在此；工具不会自动尝试未知内存偏移或降低系统保护。

当前自动流程仅放行 macOS 27.0 / Apple Silicon / 微信 4.1.13（269630）组合。
此环境需要兼容的新 LLDB；其他系统可先导入已有密钥验证读取。
向导不等同于跨所有版本的通用保证。

### B. 授权并准备

点击「授权并开始取钥」会明确说明影响。确认后，系统显示管理员授权窗口。
本次高权限任务负责官方客户端备份、临时重签、捕获、清理和恢复；普通用户进程负责
数据首部准备及 Keychain 保存。目标是减少重复授权，不保证所有系统只显示一次。

系统密码只交给系统授权窗口；应用不收集、不缓存密码。管理员授权不替代目录隐私权限。
预检会尝试只读打开数据库，并以不创建、不截断、不写入的方式打开微信的
`Info.plist`，让系统检查 App 管理权限。这个检查不改变客户端文件；若系统显示授权提示，
由用户本人确认。后台管理员任务在备份及退出微信前还会复核客户端访问权限。
开发版重新签名可能让旧授权失效，必须以当前安装版的检查结果为准。

### C. 先停在登录页，再等待真正就绪

向导按实际事件显示：备份、准备、重开微信、等待登录页确认、附加、断点安装、恢复运行。
工具关闭并重开微信是正常准备步骤。请停在微信登录页，暂不点击微信的登录按钮；
若已经进入聊天页，先退出账号并停在登录页。在向导点击「我已停在登录页，准备监听」。
此后工具才连接新的微信进程。看到「监听已就绪」后，再点击微信登录并完成手机确认。
不要把退出账号和点击登录合成一步；4.1.13 可能在退出时更换进程，必须留出重新安装断点的时间。
进程退出、重新附加和单纯重试附加使用不同状态记录，不能从「正在连接」一行推断原因。
等待过程中保持向导开启，可通过「取消并恢复」请求结束。

调试设置阶段超过 30 秒未恢复运行会退出；登录页等待与取钥监听共用 10 分钟截止时间。
恢复阶段单独完成，不能在倒计时结束时立即强杀任务；以官方客户端恢复结果为准。
无法通过校验的候选不会保存为有效密钥。
若候选未匹配预选数据库，且微信打开了另一账号目录，工具会停止、恢复官方客户端并明确提示
账号目录变化，不会让用户反复登录同一个错误目标。未通过校验的候选不能据此认定为另一账号的有效密钥。

### D. 验证与恢复

密钥必须匹配所选账号的加密数据库首部。验证通过后，先退出调试和恢复官方微信，
再由普通用户进程再次验证实际数据库并写入 Keychain。
恢复先在 `/Applications` 暂存并检查官方签名与 Hardened Runtime，再替换当前客户端；
替换后的校验失败会尝试回退。发生断电或系统强杀仍需检查任务记录并执行恢复。
最终状态必须包含「官方客户端已恢复」和「凭据已保存」。单纯拿到候选不算完成。
恢复后正常登录微信，再读一条实际消息验证。

## 取消、中断和恢复

每个任务在本机私有目录 `NoteBridge/setup/jobs/<UUID>` 留有状态。
备份为 `WeChat.original.app`，不进入仓库。
「取钥任务与恢复」列出阶段与恢复按钮；凭据已捕获但尚未保存时可继续查看并完成 Keychain 保存。未完成恢复前不要删除它。

- 正常取消：点击取消，等待解除调试和恢复完成，不能立即强杀整个流程。
- 取钥超时：检查明确失败阶段，确认官方微信恢复后再决定是否重试。
- 突然退出或断电：重新打开凭据工具，检查未完成任务，使用恢复入口。
- 恢复失败：保留原备份，通过恢复入口重新请求必要系统授权。不要再次捕获新密钥。
- 微信登录无响应：先处理调试器释放和客户端恢复，避免反复点击登录。

诊断记录阶段、版本、数量和错误类别；系统准备失败另有权限为 600 的
`failure-details.json`，保存具体准备步骤、退出状态及有限长度的系统错误信息。
不记录密钥或原始 LLDB 内存输出。`progress.ndjson` 保留进度历史，恢复成功不会覆盖失败原因。

## 密钥保存、复用和备份

主密钥保存在用户 macOS Keychain；默认不启用云同步。账号数据环境和凭据引用绑定，
后续读取项目通过本地凭据访问器或只读消息 API 复用，不需要给模型发送密钥。
Keychain 锁定、系统拒绝访问和真实密钥不匹配是不同错误。

加密备份使用 PBKDF2-HMAC-SHA512 / 256000 轮、随机盐和 AES-GCM，口令至少 12 字符。
口令不保存。导入备份后仍要验证目标数据库。备份和口令需分别妥善保存。

同账号普通重新登录、重启和新增数据库通常能复用；微信升级先验证旧密钥。
其他账号、换设备或数据重建不能假定同一密钥。密钥不是带固定有效期的登录 Token。

## 开发者命令行

```sh
native/.build/release/notebridge-access --help
printf '%s' '{"operation":"doctor"}' | native/.build/release/notebridge-access
```

凭据操作使用私有 stdin/stdout 管道。默认不提供明文密钥读取；受信任本地读取组件
需显式使用内部读取标志。HTTP 管理台没有返回主密钥的接口。
